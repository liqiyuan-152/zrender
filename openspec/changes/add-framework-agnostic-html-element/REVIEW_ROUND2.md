## 审核发现的问题及修复

### 1. API 参数名不一致 ✅ 已修复

**问题：** design.md 第 92 行示例使用 `transform: 'follow'`，而 docs-draft-api-reference.md 和文档其他部分使用 `mode: 'follow'`。

**修复：** 统一为 `mode: 'follow'`，修改 design.md 示例代码和默认值说明。

**影响文件：** design.md

---

### 2. 术语"screen 模式"可能与"屏幕坐标"混淆 ✅ 已修复

**问题：** 术语约定说"不使用屏幕坐标"，但布局 API 使用 `screen` 模式，可能让开发者误以为是物理屏幕坐标。

**修复：** 在术语约定中明确说明："`screen` 模式指**场景坐标对齐**，不是物理屏幕坐标"。

**影响文件：** design.md

---

### 3. 跨层迁移概念未明确定义 ✅ 已修复

**问题：** 多处提到"跨层迁移""跨 Canvas 迁移"，但没有明确是指 zlevel 变化、Canvas 元素更换，还是 hover 层提升。

**修复：** 在术语约定中增加定义：**跨层迁移 (layer migration)** - HTML 元素在运行时改变所属的 Canvas 层级（zlevel），或从一个独立的 Canvas 元素移动到另一个。首版不支持。

**影响文件：** design.md

---

### 4. 导出错误处理策略描述不精确 ✅ 已修复

**问题：** 
- design.md 第 77 行说在 `src/canvas/Painter.ts` 的 `getRenderedCanvas` 检查
- 但又说检查"场景成员而非仅可见显示列表"
- `src/export.ts` 的职责不清晰

**修复：** 重写导出错误处理策略段落，明确：
- Canvas 导出入口：`src/canvas/Painter.ts` 的 `getRenderedCanvas` 方法开头
- SVG 导出入口：`src/svg/Painter.ts` 的 `renderToString` 方法开头
- 检查 Storage 管理的场景元素（非仅显示列表）
- 已 `remove()` 的宿主不应阻止导出
- `src/export.ts` 仅负责符号导出，无需修改
- 限制范围：zrender 提供的方法，不能拦截直接调用 Canvas 原生 `toDataURL`

**影响文件：** design.md

---

### 5. SVG 聚焦阻断描述有歧义 ✅ 已修复

**问题：** design.md 第 75 行说"SVG 不依赖 Canvas 实验能力，但须满足公共聚焦阻断要求"，"要求"一词有歧义。

**修复：** 改为"SVG 可独立使用且与 Canvas **共享**公共聚焦阻断实现（原生 inert，缺失拒绝）"。

**影响文件：** design.md

---

### 6. 任务 2.13 的聚焦阻断策略（后续审核修订）

**问题：** 历史审核误将缺失 inert 时拒绝创建改成未经验证的降级，与最终规范冲突。

**修复：** 以最终规范为准：要求经验证的原生 inert，缺失则拒绝创建；删除组合降级及对子节点 tabindex 的修改。

**影响文件：** tasks.md

---

### 7. 性能基准任务描述过于复杂 ✅ 已修复

**问题：** 任务 3.11 在第一轮修改后变得过于复杂，包含过多的参数和条件描述。

**修复：** 简化为核心测试场景定义：
- 3 种模式：(a) 静态，(b) 每帧平移 1px，(c) 5 个宿主同时改变高度（每秒 10 次）
- 明确可接受基准：10 个宿主、模式 (c) 下 P95 帧时间 <20ms（50fps）
- 保留关键参数记录要求

**影响文件：** tasks.md

---

### 8. 任务 3.7 的导出检查位置与 design.md 不一致 ✅ 已修复

**问题：** 任务 3.7 说"在 src/export.ts 入口检查"，但 design.md 明确说入口在 `src/canvas/Painter.ts` 的 `getRenderedCanvas`。

**修复：** 修正任务 3.7 为"在 src/canvas/Painter.ts 的 getRenderedCanvas 单 Canvas 快速返回前检查"，并增加多层合成、高分辨率重绘的测试要求。

**影响文件：** tasks.md
